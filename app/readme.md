# LangApp – Руководство для новых разработчиков

Добро пожаловать в проект LangApp!  
Это Android‑приложение для изучения языков. Ниже вы найдёте всё, что нужно знать, чтобы быстро войти в курс дела: от общей идеи до конкретных классов и типичных задач.

---

## 1. О чём приложение?

LangApp помогает учить язык через интерактивные задания. Пользователь выбирает уровень (элементарный, базовый, средний, дополнительный), затем урок (1–15) и конкретный раздел. Внутри раздела – цепочка заданий разных типов: выбрать ответ, написать слово, повторить фразу, послушать диалог, изучить теорию и т.д.

Все данные (задания, тексты, аудио, картинки) хранятся в **Firebase Realtime Database**. Аудио и изображения лежат на внешних URL (например, в Firebase Storage или другом хостинге).

## 4. Как устроены данные (модели)

### 4.1. `Section` – раздел урока
- `id`, `name`, `description`
- `tasks` – список заданий (обычно загружается отдельно)

### 4.2. `Task` – задание (sealed class)
Все типы заданий наследуются от `Task`. Вот основные:

| Тип (`type`)               | Что делает                                                                 |
|----------------------------|----------------------------------------------------------------------------|
| `MULTIPLE_CHOICE`          | Выбрать один правильный вариант из нескольких                              |
| `TEXT_INPUT`               | Ввести слово или фразу в текстовое поле                                    |
| `IMAGE_INPUT`              | Посмотреть на картинку и написать, что на ней                              |
| `AUDIO_RECORDING`          | Прослушать фразу и повторить (запись)                                      |
| `TEXT_RECORDING`           | Прочитать предложенный текст и записать произношение                       |
| `ALPHABET`                 | Сетка букв – нажатие проигрывает звук                                      |
| `SYLLABLE`                 | Группы слогов (например, согласные + гласные)                              |
| `THEORY`                   | Теоретический материал с поддержкой Markdown и интерактивными вопросами    |
| `DIALOGUE`                 | Диалог с репликами (текст + аудио)                                         |
| `VOCABULARY_IMAGE_AUDIO_SET` | Словарь: слово, картинка, аудио                                            |
| `MULTIPLE_CHOICE_SET`      | Набор из нескольких множественных выборов (например, тест)                 |
| `AUDIO_RECORDING_SET`      | Несколько фраз для повторения                                               |
| … и ещё около 10 типов     |                                                                            |

Все модели помечены `@Parcelize` – их можно передавать между фрагментами как аргументы.

### 4.3. `UserProfile` – профиль пользователя
- `userId`, `fullName`, `group`, `email`
- прогресс по уровням: `elementaryProgress`, `basicProgress` и т.д.

## 5. Где и как данные загружаются?

### 5.1. Репозиторий `FirebaseRepository`
Это **синглтон**. Все запросы к Firebase идут только через него.

**Важные методы:**

```kotlin
// Получить список разделов урока (в реальном времени)
fun getAvailableSections(level: String, lesson: Int): Flow<List<Section>>

// Получить задачи конкретного раздела (тоже Flow)
fun getTasks(level: String, lesson: Int, sectionId: String): Flow<List<Task>>

// Загрузить профиль один раз
fun getUserProfile(userId: String, callback: (UserProfile?) -> Unit)

// Обновить профиль
fun updateUserProfile(userId: String, fullName: String, group: String, callback: ...)
```

Все `Flow` внутри построены на `callbackFlow` – они автоматически обновляют UI при изменении данных в Firebase.

### 5.2. Структура базы данных (важно понять)

```
Lessons/
  elementary/
    1/
      sections/
        section_1/
          name: "Алфавит"
          description: "..."
          tasks/
            task_1/
              type: "ALPHABET"
              ...
            task_2/
              type: "MULTIPLE_CHOICE"
              ...
        section_2/ ...
    2/ ...
  basic/ ...
  intermediate/ ...
  additional/ ...

Users/
  <user_uid>/
    fullName: "Иван Иванов"
    group: "Группа 1"
    email: "ivan@example.com"

UserProgress/
  <user_uid>/
    elementary: 5
    basic: 3
```

**Обратите внимание**: в `tasks` у каждого объекта обязательно есть поле `"type"`. По этому полю репозиторий понимает, какую модель создать.

### 5.3. Парсинг заданий

Метод `createTaskFromData()` внутри репозитория – большой `when` по полю `"type"`. Если вы добавляете новый тип задания, нужно:
1. Создать класс в `data.model`, наследник `Task`.
2. Добавить ветку в `createTaskFromData`.
3. Добавить константу типа в `UniversalTaskAdapter` и соответствующий `ViewHolder`.

## 6. Архитектура приложения (MVVM)

### 6.1. Основные компоненты

- **Model** – данные (репозиторий + модели).
- **ViewModel** – хранит состояние, подписывается на репозиторий, не знает про Android.
- **View** – Activity / Fragment, наблюдает за ViewModel и отображает UI.

### 6.2. Пример: `GalleryFragment` + `GalleryViewModel`

- `GalleryFragment` показывает кнопки уровней и уроков.
- При клике на урок вызывает `viewModel.loadTasks(level, lesson, sectionId)`.
- `viewModel.tasks` – `StateFlow<List<Task>>`. Фрагмент наблюдает за ним и при изменении показывает задания.
- Всё работает асинхронно, без блокировки UI.

### 6.3. Пример: `HomeFragment` + `HomeViewModel`

- `HomeViewModel` использует `UserProfileManager` (утилита-синглтон, которая хранит профиль в `LiveData`).
- При изменении профиля (редактирование) обновляется UI.

### 6.4. Навигация

Используется **Navigation Component**. В `res/navigation/` лежит граф. Переходы выглядят так:

```kotlin
findNavController().navigate(
    R.id.action_nav_gallery_to_vocabularyFragment,
    bundleOf("LEVEL_KEY" to level, ...)
)
```

## 7. Как отображаются задания (самое интересное)

### 7.1. `UniversalTaskAdapter`

Это **универсальный адаптер** для `RecyclerView`. Он принимает список `Task` и в зависимости от реального типа создаёт правильный `ViewHolder`.

**Как добавить новый тип задания:**
1. В `UniversalTaskAdapter` добавить новую константу `VIEW_TYPE_*`.
2. В `getItemViewType` вернуть эту константу для вашего класса.
3. В `onCreateViewHolder` наинфлейтить нужный layout и вернуть новый холдер.
4. В `onBindViewHolder` привести `item` к нужному типу и вызвать `bind`.

### 7.2. ViewHolder'ы (папка `holders`)

Каждый холдер отвечает за один тип задания. Например:

- `MultipleChoiceHolder` – показывает варианты ответа, проверяет правильность.
- `AudioRecordingHolder` – кнопка записи, воспроизведение эталона, отправка результата.
- `TheoryHolder` – отображает Markdown через кастомный парсер, может показывать встроенные вопросы.

**Общая логика холдера:**
- Получает задание в методе `bind()`.
- Настраивает UI (текст, картинки, кнопки).
- Обрабатывает действия пользователя.
- При необходимости сохраняет результат (пока не реализовано глобальное сохранение, но можно добавить через `onItemClick`).

### 7.3. Фрагмент задания – `TaskPageFragment`

Этот фрагмент получает один объект `Task` из аргументов, кладёт его в список из одного элемента и передаёт в `UniversalTaskAdapter`. Так мы переиспользуем один и тот же адаптер и для одного задания, и для списка.

## 9. Работа с аудио и изображениями

### Аудио
- В холдерах создаётся `MediaPlayer`, который получает URL из поля модели (например, `audioPrompt`).
- Воспроизведение по нажатию на кнопку или автоматически.
- После окончания `MediaPlayer` освобождается, чтобы не было утечек.

### Изображения
- Загружаются через **Glide**.
- Пример:
  ```kotlin
  Glide.with(context)
      .load(imageUrl)
      .centerCrop()
      .into(imageView)
  ```

### Запись аудио
В коде есть типы `AudioRecordingTask` и `TextRecordingTask`, но реализация записи и проверки произношения не показана. Предполагается, что в холдерах будет использоваться `MediaRecorder` и, возможно, внешний сервис для сравнения произношения.

## 11. Типичный жизненный цикл экрана с заданиями

1. Пользователь нажимает на урок в `GalleryFragment`.
2. Открывается диалог со списком разделов (секций). Данные загружаются через `repository.getAvailableSectionsSingle()`.
3. Пользователь выбирает раздел – вызывается `navigate()` с аргументами `level`, `lesson`, `sectionId`.
4. `TaskPageFragment` получает аргументы и через `viewModel.loadTasks()` начинает загрузку заданий.
5. `viewModel.tasks` – `StateFlow`. Фрагмент подписывается и при получении списка передаёт его в `UniversalTaskAdapter`.
6. Адаптер отображает первое (или единственное) задание.
7. Пользователь выполняет задание, видит результат.  
   (Пока нет автоматического перехода к следующему – надо добавить.)

## 12. Как добавить новый тип задания (пошагово)

1. **Создать класс модели** в `data/model`, наследовать от `Task()`, добавить `@Parcelize` и нужные поля.  
   Пример:
   ```kotlin
   @Parcelize
   data class MyNewTask(
       override val taskname: String,
       override val id: String,
       val myField: String
   ) : Task() {
       override val type: String = "MY_NEW_TYPE"
   }
   ```

2. **Добавить парсинг** в `FirebaseRepository.createTaskFromData()`:
   ```kotlin
   "MY_NEW_TYPE" -> MyNewTask(...)
   ```

3. **Добавить константу типа** в `UniversalTaskAdapter`:
   ```kotlin
   const val VIEW_TYPE_MY_NEW = 20
   ```

4. **В `getItemViewType`** добавить условие:
   ```kotlin
   is MyNewTask -> VIEW_TYPE_MY_NEW
   ```

5. **Создать layout** для холдера (например, `holder_my_new.xml`).

6. **Создать ViewHolder** в папке `holders`, наследуясь от `RecyclerView.ViewHolder`. Реализовать метод `bind(task: MyNewTask)`.

7. **В `onCreateViewHolder`** добавить создание холдера:
   ```kotlin
   VIEW_TYPE_MY_NEW -> MyNewHolder(inflater.inflate(R.layout.holder_my_new, parent, false))
   ```

8. **В `onBindViewHolder`** добавить ветку:
   ```kotlin
   is MyNewHolder -> holder.bind(item as MyNewTask)
   ```

9. Готово! Теперь задания этого типа будут отображаться.

## 13. Часто задаваемые вопросы (FAQ)

### Q: Где хранятся аудио и картинки?
A: В Firebase Storage или другом публичном хранилище. В базе лежат только URL. Например, `"image": "https://firebasestorage.googleapis.com/.../image.png"`.

### Q: Как тестировать без Firebase?
A: Можно поднять локальный эмулятор Firebase или заменить репозиторий на моковый (например, возвращать тестовые данные). Пока такой возможности нет, но структура позволяет.

### Q: Почему так много типов заданий?
A: Приложение задумано как платформа для разных языковых упражнений. Каждый тип решает свою задачу: от запоминания букв до отработки произношения.

### Q: Где логика проверки произношения?
A: Пока не реализована. В планах – интеграция с каким-либо сервисом распознавания речи (Google Speech Recognition или собственный бэкенд).

### Q: Как добавить новый уровень (например, «Профессиональный»)?
A: Достаточно добавить новый объект в Firebase по пути `Lessons/professional/...`. В `GalleryFragment` нужно будет добавить ещё одну кнопку для этого уровня. Код уже поддерживает динамическое отображение.

## 14. Полезные советы для разработки

- Всегда используйте `viewModelScope` для корутин внутри ViewModel.
- Не держите `MediaPlayer` дольше, чем нужно – освобождайте в `onDestroyView` холдера.
- Если добавляете новый тип задания, не забудьте про `Parcelable` – иначе не передать между фрагментами.
- Для отладки Firebase включите в логах тег `FirebaseRepository` – там выводятся ошибки.
- Для работы с аудио лучше создать отдельный сервис или синглтон, чтобы не плодить MediaPlayer в каждом холдере.
